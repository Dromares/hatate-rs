# The Queue view (Phase 6.d)

Work in progress; not yet a replacement for Hatate. This document belongs to
[DAN-2217](/DAN/issues/DAN-2217). It states what the Queue view ports from Python at `76c85c4`, what it leaves
to later tickets, the differences from Python that are on purpose, the documented classes the differential
could not match (each ruled by Cloud), the differential's method and counts, the measurements the design
read needs, and the two maps Phase 6 asks every ticket for (the method map and the Python test map). 6.j
checks the union of the maps across tickets.

## 1. The cut

**Ported here:** the table (a `ColumnView` over the window's `QueueModel`, 12 columns, status tiers, chips,
sort cycle, header-state save / restore / repair); the filter bar; thumbnails (the scaled decode, the
viewport pass, the loading / failed / loaded cell); the row context menu (as data in `hatate-core::table_menu`
and a popover in `hatate-gtk::queue_menu`); select-by-status and by-predicate, reset, mark reviewed, remove;
Export Results; Write Tag Files; Clear Search Cache with its size label; the persistent scrollbar and the
`THUMB` header at the minimum window size.

| Rust | Holds |
|---|---|
| `hatate-core::table_cells` | cell text, ink, chips, tooltips, sort keys, default widths, header state encode / restore / repair |
| `hatate-core::table_menu` | the context menu as data: labels, counts, enabled flags, tooltips, the ten engines |
| `hatate-core::thumb_decode` | the scaled decode (EXIF orientation, `fit_within`, triangle filter) |
| `hatate-core::entry_filter` (additions) | `summarise_selection`, `describe_hidden`, `hidden_count_text` |
| `hatate-core::sidecar::write` | the write half of Write Tag Files (6.b ported planning) |
| `hatate-core::queue::QueueModel::reorder` | the in-place reorder a sort performs |
| `hatate-gtk::queue_view`, `filter_bar`, `queue_menu`, `table_actions`, `thumbnails` | the widgets and the actions |

**Left to later tickets:**

| Ticket | Owns |
|---|---|
| 6.e | re-search entries of the menu (registered here, disabled), the Upscale and Availability entries |
| 6.f | the review page: `select_table_row` callers, the tag rail (`TagRowDelegate`), Compare, the review half of `_on_selection_changed` |
| 6.g | the Hydrus entries of the menu (registered, disabled); the Hydrus thumbnail fetch (`thumbnail_source = "hydrus"`, `_thumbnail_source`, `_known_to_hydrus`, `_decode_from_bytes`): the Rust Hydrus client has no `get_thumbnail`, so every source but `off` decodes the file on disk, which is what Python does without an access key |
| 6.h | Preferences, including the thumbnail-size change that reaches `_queue_thumbnail_regeneration` / `_run_thumbnail_regeneration` |

**Corpus pin.** This ticket changes no site parser or engine result parser, so the `hatate-rs` golden corpus

## 2. Differences from Python that are on purpose

| Difference | Why |
|---|---|
| Remove asks first; Cancel is the default | design gate 2.6. Python removes without a question. The differential counts these as a documented class (section 4, "Remove asks"). |
| Header state is `hatate-rs:1:` + 12 comma-separated widths (`h` = hidden), not a Qt blob | [DAN-2293](/DAN/issues/DAN-2293) ruled A: a Qt `saveState()` blob cannot be read without Qt. A value this build cannot read is never partly parsed. A Qt blob is refused and defaults are used. |
| The Thumb column is 84 px (Python 72) and six more default widths have a Rust-side floor | a GTK header cell is 17 px narrower than its column (DAN-2319 F5: 12 px of padding at the left, so the title lines up with the cell text, and 4 px at the right; it was 25 px); DAN-1999 F6. Python's `DEFAULT_COLUMN_MINIMUMS` are untouched. |
| First-run widths: Status 136 (Python min 120), File 130, Booru 72; File is cut in the middle | DAN-2319 F1/F5. A GTK cell is 13 px narrower than its column, so Python's 120 px Status minimum cut `Unsearched`, `Not found` and `Searching` to `Unsearc...` (118 px natural). Before / after, in px: Thumb 84 / 84, File 164 / 130, Status 120 / 136, Engine 84 / 80, Similarity 116 / 108, Size diff. 104 / 100, Booru 82 / 72, Tags 68 / 60, Cache 80 / 72, Sent 80 / 80, Reviewed 106 / 100. `SENT` ends at 922 px, inside the 924 px that a 1000 px window leaves beside the 10 px scrollbar (viewport 934); **`REVIEWED` does not fit at 1000 px** (it ends at 1022) and is reached by the sideways scroll. `queue_status_and_file_cells_fit_and_sent_is_in_view_at_both_window_sizes` pins the chip text whole and `SENT` inside the viewport at 1090 x 790 and 1000 x 780. |
| The scrollbar is 10 px wide (the toolkit's is 22), the thumb filling its trough, in every scrolled window of the app | design gate 2.4 and `tokens.css`; DAN-2319 F2. The thumb stays `ink-58` (4.33 / 4.47). `queue_scrollbar_is_10_px_wide_and_sent_still_fits_beside_it` pins the width at 5,000 rows. |
| The Wipe line and divider are a 2 px white line over a 4 px dark halo (6.f-2) | the white line alone was 1.17:1 on the light page in the no-match state (DAN-2379). `the_split_line_clears_3_to_1_on_both_pages` pins 3:1 on both pages. |
| Settings: the selected tab has a 2 px ink underline; paragraph captions wrap to the page; every page keeps its scroll bar at rest | the selected tab's fill was 1.05 / 1.11:1 and its ink step 2.15 / 2.34 (6.h F2); a paragraph clipped mid-sentence at the 560 px minimum (6.h F3); an overlay bar is invisible until used (6.i). Pinned by `the_settings_window_controls_take_the_palette_and_found_is_the_stamp` and `settings_prose_wraps_to_the_page_and_every_page_keeps_its_bar_at_rest`. |
| Row focus ring is drawn inside the row; header labels and the filter placeholder are `opacity: 1`; the thumbnail frame and scrollbar thumb use `ink-58` | measured under the 3:1 / 4.5:1 floors otherwise (section 7). `ink-58` is a mockup token; the frame tone deviates from the mockup's `ink-28`, stated here per the design acceptance. |
| The Clear Search Cache label refreshes at start-up, after a clear and when a menu opens | GTK's menubar has no about-to-show signal. Gap: opening the menubar from the keyboard (F10) does not refresh it (`menubar_keys`, 6.c, owns F10); the label is then at most one action stale. |
| Popover tooltips are set as a `tooltip` attribute on each menu item | GTK 4.14 may ignore it. Unverified; listed under "not judgeable" in the design child. |

## 3. Error shape (DAN-2116)

This ticket adds three error types, each with `kind()`, `user_message()` and `detail()`:
`error::ExportError` and `error::CacheError` (`hatate-gtk`), and `sidecar::WriteFailure` (`hatate-core`).
The window shows `user_message()`; the path and OS text go to the log through `detail()`. Pinned by
`an_export_or_cache_failure_hides_the_path_and_the_os_text` (`error.rs`) and the `sidecar.rs` write test that
asserts the shown text contains neither the folder nor `os error`.
Export failures are also the documented DAN-2116 class in section 4: Python shows `str(exc)`.

## 7. Measurements for the design read

Renderer: `crates/hatate-gtk/examples/shot.rs`, states `queue*`, on GTK 4.14 / libadwaita 1.5 under Xvfb,
cairo. Contrast: extreme-pixel method by `worktrees/DAN-2217-tools/measure-6d.py` (output `measure-6d.out`);
the shot set and the numbers are regenerated by the verifier at the head.

Three defects the tests could not see were fixed after measuring: the row focus ring fell outside the
clipped row (now drawn inside, `stamp_fg` on a selected row); libadwaita dimmed the header labels (1.84:1
dark / 1.79:1 light) and the filter placeholder (2.35:1 / 2.26:1) with `opacity`, now 5.12 / 5.78 and 5.26 /
5.50; the thumbnail frame (1.70:1) and scrollbar thumb (1.93:1 dark) were under 3:1 at `ink-28`, now
`ink-58`. Pinned by `theme::tests::queue_boundaries_clear_three_to_one_and_header_and_placeholder_are_not_dimmed`.

Worst text row 4.57:1 (dark, the `—` cells and the `ETA —` strip). Non-text, dark / light: thumbnail frame
4.09 / 5.18, scrollbar thumb 4.33 / 4.47, sort chevron and focus ring 10.70 / 14.35, focus ring on a selected
row 11.29 / 14.88. Five rows still read under the floor in the script; all are label boxes clipped by the
viewport (an off-screen `Sent` header at the minimum size, a half-visible 8th row).

Scroll frame timing (Xvfb, cairo, 5,000 rows, 240 frames, 40 px per frame): frames over 16.7 ms in five
runs were 2, 8, 1, 1, 1 of 240; p95 16.67 ms (one vsync); max 33 to 100 ms. The spike reported 0 of 240, so
this does not match it; load and noise could not be told apart in one session. For the design read.

Open for the design read, not fixed here: the table scrolls horizontally from `Sent` at 1,000 px and from
`Reviewed` at 1,100 px (the horizontal bar takes the bottom row's space).
